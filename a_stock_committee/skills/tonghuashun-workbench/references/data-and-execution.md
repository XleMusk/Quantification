# 数据含义与操作边界

## 1. 时间与口径优先于数值大小

每个数据至少有：证券/市场、数据所属交易日、采集时点、来源、单位、是否延迟、周期/窗口。基金还要有净值日期与公布时间；财务数据有报告期与披露日；研报有报告日期、发布时间及真正可获得全文的时间。

截图仅证明截图时点的页面内容。模块显示历史日期、周末行情、上一交易日海外收盘、延迟报价或自动滚动旧新闻时，不能统一叫“现在”。盘中数据未刷新不是零，付费字段空白不是没有资金流。

多市场比较统一时区、币种和起点。ETF、指数、个股可能使用不同单位，量的“股/手/份/张”先查字段帮助；不要默认一切都乘100。

## 2. 资金、盘口与筹码

| 字段/工具 | 正确用途 | 禁止的推断 |
| --- | --- | --- |
| 成交量/成交额 | 衡量交易活跃与实际换手的规模 | 不是净新增资金；每笔成交都有对手方 |
| 内盘/外盘 | 按供应商算法分类的成交方向 | 不是实际散户/机构身份，也不是买卖总量不平衡 |
| 委比/委差、买卖挂单 | 某时点显示的订单结构 | 大挂单可撤，不等于成交或稳定支撑 |
| 大单/特大单 | 按金额、数量、委托归并等规则分类 | 一笔大单不必是机构；拆单后的机构也可能显示为小单 |
| 主力净额/净比 | 同口径观察主动性交易与相对强度 | 不等于实际机构资金净入市、账户持仓变化或国家队买卖 |
| DDE | 基于L2与分类算法的资金结构指标 | 与普通资金流统计不一定同口径；不能叠加当作两份独立资金 |
| 今日/多日增仓 | 该页模型定义的统计量 | 不是所有账户真实仓位增减 |
| 散户数量 | 模型标签/指标，先查具体定义 | 不是实际证券账户数量 |
| 筹码分布/火焰山/COST/WINNER | 历史成交与换手假设下的成本分布估计 | 不是中登账户存量，不证明某主力买完/卖完 |
| 龙虎榜及持有预估 | 公开上榜交易、基于有限记录的估计 | 不是完整持仓账本，未上榜不等于未交易 |
| ETF份额 | 基金份额变化，可结合NAV估算申赎变化 | 与场内大单净流入/成交额不可互换 |

官方旧版[资金分析说明](https://www.10jqka.com.cn/ad_mar/help/zjfx.html)将流入/流出解释为主动性成交分类；[DDE说明](https://www.10jqka.com.cn/ad_mar/help/dde.html)另有基于L2的分类。现行[日频资金字段文档](https://quant.10jqka.com.cn/view/dataplatform/detail/558)也区分主/被动和订单大小。不同产品与页面不可直接套同一阈值。

这里的研究判断是：以上分类记录并不提供所有参与者的真实账户身份和库存，因而无法证明“主力已经全部出货”。这是对数据可识别范围的限制，不是拒绝分析卖压与承接。

## 3. 量能、均价和技术图形

- 量比通常与近期同类成交速度比较，具体基准天数/时段依页面口径核实。开盘量比不能与尾盘直接比较。
- 累计成交额应对比相同分钟的历史值；不把午盘金额除以昨天全天金额当完整缩量结论。
- 分时均价线、指数领先线、等权/加权曲线名称可能因品种变化；不只凭黄白颜色认含义。
- 大量上涨可表示分歧放大，也可表示需求强；要看收盘位置、回踩、相对强度及后续表现。
- 前复权、后复权、未复权会改变历史价位。做结构比较需要一致口径，真实委托必须核当前未复权价格。
- 当前未结束的K线及指标会继续变；已经绘出的跨周期指标未必在当时可知。
- BOS、FVG、OB等是分析结构标签，不是同花顺必然内置功能，更不是机构身份识别。按项目框架解释时要画明形成与失效条件。

## 4. 公式的特殊风险

本机 `system\同花顺方案\func_help` 中的原始帮助是语法核对来源，生成目录只保存名称/作用域/路径，不复制全部帮助正文。

| 函数族 | 使用注意 |
| --- | --- |
| MA、EMA、SMA、HHV、LLV、COUNT、CROSS、REF | 核平滑定义、周期单位、初始样本与边界；REF是过去引用但整条公式仍可能含未来信息 |
| REFX | 本机帮助定义为引用之后周期的数据，不作为当时可执行预测依据 |
| BACKSET | 可以修改先前位置的信号；历史显示可能回写，需按逐时可见性重放 |
| ZIG、PEAK、TROUGH及关联函数 | 转折可能需后续行情确认或改写，不能把最终图形当实时信号 |
| DYNAINFONEW | 本机说明强调实时变化且不保留历史；不得拿当前值回填历史每根K线 |
| VOL、AMOUNT_IND、NEWVOL | 累计量、区间量、即时量等含义随函数/周期变化，不能用名字猜单位 |
| COST、WINNER | 估算的成本分布与获利盘，不是真实持仓核验 |
| 财务、股本、板块函数 | 注意披露日、历史修订、成分变更和停牌数据；当前成分不代表历史成分 |

外部公式先读源码，不调用附带程序，不删除原指标。编译通过只证明语法，不证明无前视/无重绘/可盈利；必须通过逐时重放与样本外检验才讨论预测能力。

## 5. ETF/LOF口径

`相对参考价值的折溢价 = 场内价格 / 参考价值 - 1`。

先标清参考值是官方历史NAV、实时IOPV还是自行估值，是否同币种、是否含停市成分和滞后报价。基于上一净值的“溢价”在境外市场大幅变化时可能失真；官方IOPV也不应无条件视为完美实时价值，须看具体基金文件。

同花顺用于显示与筛选；基金契约、申赎公告、费率与风险提示回到基金管理人/交易所原文。境内股票ETF与跨境ETF等交易机制可能不同，T+0/T+1、涨跌幅和申报单位按具体产品当前规则查证，不由名字推断。

## 6. 账户字段不能望文生义

本次截图展示的是银河证券嵌入面板，字段可能受日初余额、当日成交、清算和券商实现影响。以下是核对方法，不是声称已经取得该券商每列完整规格。

| 字段 | 应怎样核对 |
| --- | --- |
| 股票余额 | 不能单独用来确认当前持仓；与实际数量、当日买卖及市值交叉核对 |
| 实际数量 | 判断当前持仓的重要字段，仍需同一账户最新刷新与成交回报验证 |
| 可用余额 | 通常用于可卖数量判断；T+1、冻结、未成交卖单可能导致小于实际持仓 |
| 冻结数量 | 不直接等同持仓，更不能见负数就推断卖空；券商口径未知时结合委托查询解释 |
| 成本价 | 可能为摊薄成本，包含当日做T或累计已实现损益影响，不等于最后一次买价 |
| 市价/市值 | 核价格时间和实际数量；已清仓残留行有市价不代表还持有 |
| 当日买入/当日卖出 | 还原数量变化，用成交查询而非委托数量验证 |
| 持仓盈亏/当日盈亏 | 两种统计口径可能不同；不直接加减推算每一笔盈亏 |
| 可用金额/可取金额 | 能买和能取不是一回事，受交收和冻结影响 |
| 股票市值/总资产 | 同期对账，未解释的差额不擅自填补 |

如旧股票余额非零，而实际数量、市值为零且当日卖出有记录，应按已卖出待核实处理，不继续称“全仓持有”。做T后成本变化应看成交明细，不能只凭截图亏损比例评价操作。

## 7. 可执行操作的分层

| 类型 | 处理原则 |
| --- | --- |
| 查询、读图、打开资料、筛选 | 在用户任务范围内可协助；控制工具必须可用，成功后读回页面 |
| 自选、画线、布局、公式、提醒持久修改 | 对应明确请求，保留原设置；提醒不要升级成条件交易 |
| 下单预填 | 单独明确代码、市场、方向、数量、价格、账户、委托类型；核真实资金与可卖量 |
| 下单提交、撤单、转账、条件单启用、账户清仓 | 本次未授权；遵守项目关闭实盘及另行验证要求，不推定持续授权 |
| 登录、验证码、支付/订阅、社区发送 | 不因学习软件就执行；凭据不读取不记录 |

已有适配层仅提供限定范围的人工提交前预填，见 `D:\Quantification\trading\ths\README.md`。其“测试通过”不代表本机账户联调完成。首版品种限制、窗口映射、原始人民币价格、可用资金、数量和有效时间检查必须保留，不能因为研究对象是ETF就绕过支持范围。

在当前会话没有原生桌面控制能力时，不暗中通过内存修改、窗口消息、隐藏快捷键、猜坐标等方式替代。公共配置中的ID只用于理解，不作为命令执行。

## 8. 执行后的核验

导航后核页面名/证券/周期；筛选后核解析条件与行数；提醒后核规则与启用状态；持久改动后核保存结果。

若将来另行授权交易，仍必须区分计划、预填、已提交、已受理、部分成交、全部成交和撤单结果。未知状态只查询，不重发；凭提示框或市值变化不能认定具体订单成交。当前工作不发送任何真实委托。
