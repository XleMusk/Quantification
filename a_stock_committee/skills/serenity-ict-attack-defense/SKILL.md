# Serenity + ICT A股攻防总控

这个 skill 是项目内调用层，不替代 `serenity-skill`、`ict-strategy` 或原投委会；它规定三者的顺序和互相否决条件。

## Core Rule

先判断能不能进攻，再判断攻哪里，最后判断怎么买。

1. 用 Serenity 先排产业链层级和证据强度：真实需求、系统变化、产业链卡点、候选公司、反方证据。
2. 用 ICT 再排技术结构：高低点结构、流动性扫荡、FVG/OB、放量位、失效位。
3. 用原 A股投委会落地：市场状态、风控红灯、仓位计算、T+1/涨跌停/流动性、交易记忆。

没有产业链证据，只能观察；没有结构买点，只能等；没有仓位边界，禁止进攻。

## When To Use

- 用户问今天或未来几天/几周“进攻什么板块”“防守怎么做”“能不能抄底”。
- 用户明确不想只看当日涨幅，希望把消息面、产业链和技术结构合起来。
- 用户讨论半导体、商业航天、卫星互联网、AI算力、机器人、CPO、创新药等主题。
- 用户要求复盘此前预测哪里短视、哪里证据不够、怎么改进。

## Workflow

1. **Regime Gate**：先用项目市场状态判断总仓位。
   - 强修复/主升：允许主攻，但仍需止损和单票上限。
   - 弱修复/震荡：只做前排分歧低吸或中军确认，不追后排。
   - 退潮/破位：只允许小仓试错或防守，优先保护本金。

2. **Serenity Layer**：先排产业链层级，再排股票。
   - 输出“卡住的环节 / 产业链位置 / 证据 / 市场可能没看清的地方 / 反方理由”。
   - 至少指出一个热门但应降级的方向，避免只追热度。
   - 当前消息必须联网或用本地行情/公告数据核验。

3. **ICT Structure Layer**：把候选变成交易计划。
   - 先看日线/60分钟趋势，再看 15分钟或分时承接。
   - 标记买方/卖方流动性、前高前低、FVG/OB、BOS/CHoCH。
   - A股不能机械套用美股 killzone；重点看开盘 30 分钟、午后回流、尾盘确认。
   - 因 T+1，盘中追高后当天不能纠错，必须降低仓位。

4. **Committee Risk Layer**：用本项目命令做落地检查。
   - `market-regime`：判断市场环境。
   - `intraday-breadth`：判断盘中宽度。
   - `risk-radar`：检查公告/监管/退市/ST/传闻风险。
   - `position-sizer`：把止损位转换为可买股数。
   - `trader-memory`：登记 thesis，后续复盘判断是研究错还是执行错。

## Attack/Defense Output

每次输出必须包含：

- 总判断：进攻 / 轻进攻 / 防守 / 空仓等待。
- 主线优先级：先排产业链层级，再排标的。
- 交易触发：什么结构出现才允许买。
- 失效条件：什么情况说明判断错了。
- 仓位边界：总仓位、单票仓位、试错仓、加仓条件。
- 防守动作：破位、炸板、低开、跌破成本、指数失守时怎么处理。
- 待核验清单：公告、财报、订单、客户、海外映射、ETF溢价、指数关键位。
