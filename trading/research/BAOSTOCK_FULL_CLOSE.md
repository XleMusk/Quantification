Run `env/python.exe -m trading.research.baostock_full_close --day 2026-10-14 --sdk-wheel <reviewed 0.9.4 wheel> --out D:/QuantificationData/trading/research/full_close/baostock_20261014_v1 --max-new-queries 200`.

One exact-day `query_all_stock` response fixes all ordinary Shanghai/Shenzhen A shares, including suspended and ST observations. The immutable plan splits this full roster into twenty-symbol batches. The budget bounds new queries in this run; rerun the exact command with another positive budget to resume only unattempted symbols. Partial checkpoints never constitute a full-market close. Provider, raw-quality and interrupted-query failures remain preserved and are never automatically retried.

Ordinary new jobs also renew protected source sessions after at most 200 new price queries by default. `--max-queries-per-session 200` makes this explicit; only values 1 through 200 are accepted. For an entire fresh dated roster, supply a sufficiently large explicit run budget, such as `--max-new-queries 6000`; the immutable roster still strictly bounds the actual queue. Clean budget resumes append closed session records rather than erasing earlier runs. This does not make a failed generation resumable.

Historical source repair requires the explicit `--historical-research-repair` option and a separate output folder. The actual current clock and target-year pinned calendar must show that the requested date is an open session whose 15:00 close has passed. Its own exact-day `query_all_stock` response fixes the whole ordinary roster; a later roster cannot substitute. `historical_repair_manifest.json` records this distinct mode, target day, calendar and roster identity. Without the option, the normal latest-closed-day rule is unchanged. No historical repair rewrites StockDB, native features or another generation.

Prices use raw `adjustflag=3`, exact one-day requests and the existing daily-slice validator/checkpoint. Nullable suspended volume, amount and return remain blank; source inventory completeness differs from Engine-bar coverage. One protected anonymous market-data session serves sequential price batches at the existing minimum 0.5-second interval. No StockDB, account, broker or Ledger is changed.

`load_complete(folder)` is strictly read-only and returns `(raw_dataframe, metadata)`. It rejects incomplete/failed jobs, changed roster or raw bytes, missing/duplicate symbols, same-day roster/price status disagreement and changed research boundaries. Metadata includes `plan`, `receipt`, `ordinary_roster`, `source_folder` and `read_only_verified`. All source values remain strings, including blanks. ## Explicit transport recovery generation

The original failed generation remains immutable and ordinary resume still refuses it. For the evidenced single connection reset only, `env/python.exe -m trading.research.baostock_full_close_recovery --parent <failed-v1> --out <new-v2> --sdk-wheel <wheel> --max-new-queries 4652 --session-query-limit 200` creates a separate generation. It verifies and copies completed raw responses, retains the same dated roster and request plan, and records parent attempts separately from inherited rows, new price queries and the independent exact-day `query_trade_dates` health query. A passing health response permits exactly one explicit recovery attempt of the prior failed code; this means two total attempts, not zero retries. Any health, schema, quality or later transport failure stops the new generation. There is no recovery chain or retry loop.

The new source sessions rotate after at most 200 new price queries. This limits long-session exposure; the observed reset does not prove a provider service limit and rotation does not guarantee success. The strict complete loader revalidates original lineage, preserved parent bytes, exact roster, inherited raw hashes, health response and per-session counts. `full_close/active_job.json` locates the current generation and processes; authoritative process identity and terminal receipts still determine their state.
