# Google 工程实践在 Quantification 的落地规则

本文件把 `Quantification_Google_Applied_Design_20261026.pdf` 的设计决定转换为当前仓库可以执行的工程规则。它是项目内部的应用说明，不宣称 Google 的私有制度，也不替代 `AGENTS.md`、`docs/CODE_STYLE.md` 或各工作包的业务契约。

## 先交付产品旅程

每个工作包必须至少完成一条可复现旅程，并写出真实输入、输出和失败边界：

| 旅程 | 当前系统的可交付结果 | 不能冒充的结果 |
| --- | --- | --- |
| 财报研究 | 固定来源、披露窗口、决策截止、事实和因子回执 | CSV 诊断不能冒充 PIT 财报账户 |
| 日终运行 | 固定收市输入、D0/D1 目标、纸面订单、账户连续性 | 观察价投影不能冒充未来成交 |
| 故障恢复 | 受影响范围、原始回执、可恢复状态和下一游标 | 重试请求不能冒充账户重新创建 |
| 模块扩展 | 新来源或新策略复用 Signal → Target Portfolio → Orders → Fill → Cash/Position | 新策略不能新建第二套余额或任务登记 |

## 代码结构规则

采用四层职责，但不为形式新建服务：

1. **入口层**：CLI、HTTP 和日程只解析配置、运行身份和时间上下文。
2. **应用用例层**：提交研究、冻结计划、推进纸面账户、查询结果；负责状态和幂等。
3. **业务核心层**：事实选择、因子、信号、目标组合、Engine/Ledger；纯计算不读环境、不读当前时间、不接触供应商。
4. **适配层**：StockDB、财报来源、快照、SQLite、文件和 THS 只读观察；返回带来源和失败语义的事实。

研究 job、账户 run、某次决策/计划必须使用不同身份，并通过显式字段关联。数据获取和研究计算不能直接写生产余额；所有持久余额变更仍由既有账户 worker 与 Ledger 事务完成。

## AI 生成代码的重构顺序

重构按“行为先于外观”的小变更推进，每个变更只改变一种性质：

1. 先保留已正确的 Engine、Ledger、分配器、快照和恢复逻辑。
2. 在输入边界一次性校验形状、单位、时间视图和范围，内部函数消费明确类型。
3. 把混在 API/worker 中的业务规则按真实变更原因提取；不按文件长度机械拆分，也不引入万能 `Manager` 或第二套 registry。
4. 每个修复同时加入正常例、关键边界和真实失败例；失败必须是显式 `BLOCKED_*`/`UNKNOWN_*`，不能用空列表伪装成功。
5. 迁移旧调用者后再删除别名；旧路径要记录用户、退出条件和删除点。

## 交付门槛

一个工作包只有在以下条件都满足时才算完成：

- 有最终代码或固定研究产物，并能由项目解释器复跑；
- 有实际消费者（纸面账户、研究回执、工作台或发布包）；
- 有独立预期和测试，测试结果不依赖隐藏的系统日期或任意最新文件；
- 结果绑定 `run_id`、`snapshot_id`、`decision_id`、时间语义和输入哈希；
- 失败、缺数和未获准执行均保留回执；
- 发布包记录 commit、工作树状态、执行闸门和缺失项。

测试数量、Agent 数量、代码行数和“审计通过”都不是交付指标。优先衡量：任务是否完成、判断是否可解释、恢复是否可继续，以及从就绪输入到结果的耗时。

## 当前主线映射

按当前未完成路线推进，不因为某一路线缺数据而停止其他路线：

| 主线 | 下一可执行节点 | 通过条件 |
| --- | --- | --- |
| A 收市与 D0/D1 | 完整 StockDB close package → fixed_daily → 下一日纸面账户 | 精确标的覆盖、日期和哈希一致；无伪造缺失值 |
| B 策略比较 | 同快照、同费用、同窗口的固定腿/候选腿和联合结果 | 有共同窗口指标和明确 `CONTINUE/STOP_RESEARCH_ONLY`，不自动晋级 |
| C F2 PIT | 真实发布来源的 `publication/asof/revision` 证据 → F01 | 决策截止前可用、期间和单位可解释；否则保留 `BLOCKED_DATA` |
| D THS | 授权范围内只读观察与回读 | 有原始导出、时间、证券和哈希；不登录、不预填、不提交 |
| E 工作台与发布 | 可重连 job、可下载结果、可恢复纸面账户和内部 release | 同一 `job_id`/`run_id` 可追查，发布可重建，执行闸门仍关闭 |

## 评审与提交习惯

提交应是一个可解释的小变更：说明用户旅程、行为差异、保持不变的边界、测试命令和证据路径。结构重构、业务修复和研究规则变化分开提交。代码评审优先检查设计、功能、复杂度、测试和文档；只有整体健康度改善时才接受“赶进度”的理由。

当前所有发布继续保持 `execution_admitted=false`、`NO_TRADE`、`candidate_panel_only=true`。真实券商/同花顺登录、报单、撤单、转账和付费数据不属于本路线的可执行节点。

## 已落地的首个 Google 应用切片（2026-10-27）
